# 03 · 渲染与视觉

> 状态：**讨论中** · 草案 v0.1
>
> D6 已定方向：**默认极简，但效果层必须是可插拔的注册表**——因为后面要加箭头、
> 模拟手绘圈、脉冲等等，不能每加一个效果就改一次渲染代码。

## 1. 画面分层

屏幕上其实是三种东西叠在一起，**它们的内存特性完全不同**，所以要分开处理：

```
┌─────────────────────────────────────────────┐
│ ③ 效果层：光环 / 箭头 / 圈画 / 卡片 / 进度条   │ ← 逐像素 alpha，一个贴合包围盒的窗口
├─────────────────────────────────────────────┤
│ ② 遮罩层：压暗的纯色矩形（若干块，无位图）      │ ← 统一 alpha，GDI 填色，零位图
├─────────────────────────────────────────────┤
│ ① 真实桌面：用户的 Excel、浏览器……             │ ← 点击直接落在这里
└─────────────────────────────────────────────┘
```

目标在 ② 里被"挖空"，所以看起来是亮的。① 永远能收到点击。

## 2. 遮罩层：不做全屏位图

这是"内存不随分辨率膨胀"的关键决定。

**做法**：把"屏幕矩形 − 洞"分解成若干矩形，每块矩形是一个纯黑、统一 alpha 的分层窗口。

```
屏幕 S = (0,0,1920,1080)
洞   H = { (812,132,32,32) ⊕ 6px }

按 y 边界切成 3 条横带，每带取洞的 x 区间的补集：
  ┌───────────────┬───┐
  │   带1 (整宽)   │   │
  ├───────────────┼───┤  ← 中间这条被洞切成左右两块
  │  左          │洞│右 │
  ├───────────────┴───┤
  │   带3 (整宽)       │
  └───────────────────┘
→ 4 个矩形窗口
```

- 每块窗口：`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`
- 用 `SetLayeredWindowAttributes(hwnd, 0, alpha, LWA_ALPHA)`，alpha = `dim × 255`，**不需要 UpdateLayeredWindow**
- 窗口数：N 个洞 → 最多 2N+2 块；日常 N=1，就是 4 块
- **保护阈值**：矩形数 > 24 时，退化为"一块整屏逐像素窗口 + 预烘焙遮罩位图"，
  避免上百个小窗口拖慢合成

内存收益：1920×1080 和 3840×2160 都是 4 块纯色窗口，**占用与分辨率无关**。

> 圆角问题：矩形分解只能出直角，但光环是圆角的。解决办法是让光环的描边**压在洞口边缘**
> 上：洞只比目标外扩 3px（等于光环宽度），光环的描边正好覆盖这条缝。
> **padding 必须 ≤ 光环宽度**，否则环外会露出一圈没被压暗的亮边——这会毁掉整个观感。

## 3. 效果层：DrawOp 管线

效果层不直接画，先生成一份**矢量指令列表**，再统一光栅化。这样效果是可测试的纯函数。

```rust
enum DrawOp {
    FillRoundRect { rect: RectF, radius: f32, color: Color },
    StrokeRoundRect { rect: RectF, radius: f32, width: f32, color: Color },
    StrokePath { path: Path, width: f32, color: Color, cap: Cap, join: Join },
    FillCircle { center: Point, radius: f32, color: Color },
    Text { origin: Point, text: TextRef, color: Color },
}
```

```rust
pub trait Effect {
    fn name(&self) -> &'static str;
    /// 向目标外扩多少（物理像素），用来算效果窗口的包围盒
    fn margin(&self) -> f32;
    /// 针对一个目标，直接往画布上画
    fn draw(&self, canvas: &mut Canvas<'_>, target: RectF, ctx: &Ctx<'_>);
}
```

> **实现修正（2026-10-19）**：初版设计是"效果产出 `Vec<DrawOp>`，渲染层统一光栅化"。
> 实际落地时去掉了这层中间表示——效果直接往 `Canvas` 上画。理由：`DrawOp` 要么退化成
> tiny-skia 的薄封装，要么就得自己实现一套路径语义，两头不讨好。效果仍然是
> **(target, ctx) 的纯函数**，照样能在没有桌面的环境里做离屏快照测试。

注册表：

```rust
pub fn build_effects(names: &[String]) -> Vec<Box<dyn Effect>> {
    // 名字 → 构造器；未知名字忽略（前向兼容），全未知时退回 ring
}
pub const KNOWN_EFFECTS: &[&str] = &["ring", "brush"];
```


**向前兼容规则**：遇到不认识的 `kind`，忽略并 `warn`，不报错。这样新版配置在旧客户端上
仍能运行（用户升级是渐进的）。

### 内置效果

| name | 长什么样 | 状态 |
| --- | --- | --- |
| `ring` | 圆角描边，默认 3px | ✅ 已实现 |
| `brush` | **模拟手绘圈**：抖动椭圆 + 平滑曲线，用目标位置做种子，重绘不会抖 | ✅ 已实现 |
| `glow` | 柔和外发光：由外向内叠 6 层逐渐变浓的描边 | ✅ 已实现 |
| `arrow` | 从卡片边缘弯向目标，带箭头；距离太近（贴着）自动不画 | ✅ 已实现 |
| `crosshair` | 四角准星：在四角外侧画四个直角，不包围目标 | ✅ 已实现 |
| `pulse` | 呼吸，alpha 0.85→1.0 | ❌ 已决定不做：每秒 60 次全窗口重绘，为一点花哨持续耗电不值 |
| `badge` | 步骤药丸，画在目标左上角；只在**多目标**时出现，单目标走标题行 | ✅ 已实现 |

`brush` 的实现值得一提：它只是"把矩形扰动成一条闭合曲线，再用 dash 来逐段显示"，
约 40 行——**能这么便宜，是因为效果层是矢量的**。如果一开始就把最终画面烘焙成位图，
后面加任何一个效果都得重做。

### 动画调度

- 一个 16ms 定时器，**只在需要时启动**：存在未完成动画，或倒计时进度条在刷新
- 动画结束后立即停表 → 静态画面 CPU 归零
- 进度条每 100ms 重绘一次整张卡片的位图（卡片通常只有 300×100 出头，重传这点数据
  比重算脏矩形便宜）。`prcDirty` 局部提交的优化做过评估，收益不足以抵消复杂度

## 4. 文案卡片（callout）

| 项 | 规格 |
| --- | --- |
| 背景 | 深色主题 `#1B1B1F` 94% / 浅色主题 `#FAFAFC` 96%，圆角 10 |
| 边框 | 1px `rgba(255,255,255,0.08)`（替代阴影，静态、零成本） |
| 内边距 | 四周统一 12 |
| 标题 | 12px，深色主题 62% 白 / 浅色主题 70% 黑，单行省略 |
| 正文 | 14px，行高 1.45，深色主题 `#FFFFFF` / 浅色主题 `#18181C`，按宽度自动折行；超过 512px 高会截断并返回 `warnings` |
| 最大宽度 | `max_text_width`，默认 336 |
| 字体（Win） | `Microsoft YaHei UI` → `Segoe UI` |
| 字体（mac） | `PingFang SC` → `Helvetica Neue` |
| 进度条 | 底部 2px，accent 色，从满到空（`--timeout 0` 时**不画**） |
| 停止按钮 | 右上角 16×16：**空心圆 + 内部方块**（停止图标），柔和的红色；距上、右各 12px，和左内边距对齐 |
| 动作按钮 | 底部一个**铺满卡片内宽**的胶囊：强调色淡填充 + 白字；还有下一步时是「下一步」，最后一步是「完成」，**两者只会存在一个** |
| 鼠标指针 | 停在停止按钮和动作按钮上时变成手型（IDC_HAND），其余地方是箭头 |
| 键帽 | 正文下一行的快捷键提示（如 Ctrl+B），字号 -4，胶囊 + 1px 描边 |
| 悬停反馈 | 文字上悬停只暂停倒计时，**不改画面**；按钮上悬停只换光标 |
| 卡片底色 | 不透明：留透明会让底下的文字透上来，看起来像脏了 |

### 摆放算法

八个候选方位（上 / 下 / 左 / 右 / 四个对角），逐个算卡片矩形并打分：

1. **硬性**：完整落在目标显示器的 work area 内
2. **硬性**：不与 target 重叠（留 8px 间距）
3. 同分时按固定优先级：下 → 上 → 右 → 左 → 四个角

`--placement top|bottom|left|right` 会把指定方位挪到优先级最前面；那一侧放不下就
退回自动顺序，**不会硬塞**——宁可换个方向，也不要让卡片压在目标上。

都放不下 → 取"溢出 work area 面积最小"的方位，再把卡片夹回 work area 内。
夹回来的位置通常仍贴着目标，指向关系不会丢。

> 实现细节：候选框先**沿垂直轴贴回 work area**（保持尺寸、只平移，不缩小）。
> 否则一个贴着屏幕右边缘的按钮，会因为"居中放在下方"横向溢出而被判为不可用，
> 卡片被迫换到左边——而用户期待的其实是"就在它正下方"。

## 5. 命中测试与悬停

遮罩**拦截**点击：被压暗的地方点不动，用户只能操作高亮区域和卡片上的按钮。
这是刻意的——引导过程中误点别处，后续步骤的坐标就对不上了。

| 区域 | 行为 |
| --- | --- |
| 遮罩窗口所有地方 | 拦截点击（`HTCLIENT`），不做任何事 |
| 效果窗口，停止按钮 28×28 命中区 | 接收点击 → 结束画面，结果记为 `stopped` |
| 效果窗口，动作按钮（胶囊） | 接收点击 → 下一步，或结束并记为 `completed` |
| 效果窗口，其余部分 | `HTTRANSPARENT`，点击落到下面的应用 |

### 悬停检测为什么不用全局钩子

要判断"鼠标是否停在文字上"，有两条路：

- `WH_MOUSE_LL` 全局低级钩子：实时、精确，但需要常驻钩子、可能被杀软盯上、要为
  "钩子超时"处理降级
- **`GetCursorPos` 轮询**：每 80ms 取一次鼠标坐标，跟卡片矩形做点包含判断

选轮询。原因是它只读、无副作用、不会被安全软件当成键盘记录器，代价是一个 80ms 的定时器
（每次调用几十微秒）。**只在有倒计时在跑的时候才轮询**，静态时零开销。

> 这条也顺手把 D3 里"预留点击观察"的接口做实了：将来要看"用户有没有点中目标"，
> 轮询 + `GetAsyncKeyState` 就能做到**观察而不拦截**，不需要升级成钩子。

## 6. 视觉令牌

```toml
[visual]
dim           = 0.55          # 遮罩不透明度
accent        = "#FF3B30"     # 光环 / 进度条
radius        = 10            # 圆角（物理像素）
ring_width    = 3
ring_contrast = "#FFFFFF"     # 双色描边的内层，保证任何背景下都看得见
padding       = 6             # 洞相对 target 的外扩
```

入场合成的克制程度是这个产品的"气质"：120ms 淡入 + 0.98→1.0 的微缩放，**不做弹跳、
不做飞入**。它是来帮你找东西的，不是来表演的。

> 上面所有数值的单位都是**96 DPI 下的逻辑像素**。实际渲染时统一乘以目标显示器的
> 缩放比，所以 200% 的 4K 屏上卡片和字会等比放大，而不是缩成一小块。

## 7. 配置文件

路径：`<数据目录>/config.toml`。Windows 上默认 `%LOCALAPPDATA%\spotlight\config.toml`，
可用 `SPOTLIGHT_HOME` 整体改到别处。全部字段可选，缺省即默认值。

```toml
[visual]
theme      = "dark"      # dark | light，决定卡片配色
accent     = "#FF3B30"   # #RRGGBB 或 #RRGGBBAA
dim        = 0.55        # 0.05–0.90
radius     = 10          # 光环圆角
ring_width = 3

[callout]
font_px        = 14
max_text_width = 336

[effects]
default = ["ring"]       # 没显式传 --effect 时用这组

[pause]
cap_seconds = 60         # 悬停累计暂停上限

[hotkey]
dismiss = "Ctrl+Alt+Esc" # 关闭当前画面的全局热键，至少要有一个修饰键
```

容错规则：文件不存在 → 全默认；**某个字段写错 → 只有该项回退默认值**并留一条说明；
数值越界 → 夹到安全区间。`spotlight doctor` 会显示配置路径、是否加载成功、以及那条说明。

AI 也可以在单次调用里覆盖：

```bash
spotlight show --capture c-7 --rect 812,132,32,32 --text "点这个按钮" --effect ring --effect brush
```

## 8. 性能预算

| 场景 | CPU | 内存增量 | 说明 |
| --- | --- | --- | --- |
| 守护进程空闲 | ~0% | 0（基线 ~10MB） | 无定时器、无窗口 |
| 静态显示 1080p | 0%（仅首帧） | +2MB | 4 个纯色窗口 + 一张卡片位图 |
| 动画中（60fps） | < 3% 单核 | +2MB | 只重绘效果窗口 |
| 静态显示 4K | 0% | +2MB | **不随分辨率膨胀** |
