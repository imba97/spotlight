# 00 · 问题与目标

> 状态：草案 v0.1

## 1. 场景

### 1.1 主场景：AI 教用户操作软件

用户："Excel 里这个表格的边框怎么去掉？"

AI 能看懂截图，也能写出正确的步骤，但只能给出"在『开始』选项卡，字体旁边那个田字格按钮"这种
描述。用户要在几十个图标里找一个自己不认识的图标——这就是当前方案的失败点。

有 Spotlight 之后：

```
AI:  [截图] → 找到目标 → spotlight show --rect 812,132,32,32 --text "点这个『边框』按钮"
用户：[屏幕上其余部分变暗，那个按钮被圈出来，旁边写着"点这个『边框』按钮"]
```

### 1.2 延伸场景

| 场景 | 说明 | 对设计的额外要求 |
| --- | --- | --- |
| 软件教学 / 录教程 | 一步步引导，可以慢 | 步骤序号、多步切换 |
| 远程协助 | 同事或客服在电话里指导 | 低延迟、不需要视频 |
| Agent 兜底 | 自动化脚本卡在某个不认识的状态 | 可由程序触发，不依赖人 |
| 无障碍 | 弱视用户需要更强的视觉锚点 | 高对比度主题、可放大 |

### 1.3 谁在调用

**主要调用方是 AI Agent，不是人。** 这会改变 API 的设计取向：

- 参数要少，默认值要对（模型不该被迫理解 DPI）
- 错误信息要能自我修复（"矩形超出显示器 2 的范围，可用范围 0..2560"）
- 输出必须机器可解析（`--json`，稳定字段名）
- 一次调用成功 > 灵活性

## 2. 产品定义

一次 Spotlight 调用的最小语义：

```
输入：一个矩形（或一组矩形）+ 可选文字 + 可选样式
输出：屏幕上不可交互的视觉指示，除此之外什么都不改变
```

"什么都不改变"很重要——不改剪贴板、不抢焦点、不模拟输入、不留窗口在任务栏、
不写注册表（便携模式）、不联网。

## 3. 硬约束

这五条是整个设计的"第一性约束"，后面所有技术选择都要服从它们。

### C1 坐标必须由工具负责对齐

AI 拿到的是**截图像素**，屏幕要的是**物理像素**，中间隔着：

- 多显示器（坐标原点可能为负，副屏在主屏左边时 x < 0）
- DPI 缩放（125% / 150% / 200%，且每台显示器可能不同）
- 截图工具自己的缩放（很多截图 API 会按 DPI 虚拟化返回 0.8 倍的图）

让模型去算这个换算，等于让它每次都掷骰子。**结论：Spotlight 自己截图，并把
"这张图的像素 → 屏幕物理像素"的变换和截图一起返回。** AI 只需要在它看到的那张图上量坐标。

### C2 遮罩必须可看不可点

如果遮罩拦截鼠标，用户就点不到被高亮的目标——产品直接失效。

→ 遮罩窗口必须 `WS_EX_TRANSPARENT`，点击穿透到下面的真实窗口。
唯一的例外是卡片角上那个 **28×28 的关闭按钮**（用户必须有办法自己关掉它），
其余区域一律穿透。

### C3 遮罩不能污染截图

AI 下一步还要截图。如果遮罩出现在截图里，AI 会看到自己上一轮画的红框，
轻则误判，重则陷入"越画越乱"的死循环。

→ 遮罩窗口必须 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，
并且 Spotlight 自己的截图接口在截图前主动隐藏遮罩。

### C4 不能有"程序启动感"

调用发生在用户正在操作电脑的时候。任何白闪、窗口动画、任务栏图标跳动、焦点切换，
都会打断用户当前的操作。

→ 无焦点窗口（`WS_EX_NOACTIVATE`）、无任务栏项（`WS_EX_TOOLWINDOW`）、
无开场动画，第一帧就是最终画面。

### C5 体积和占用是产品前提，不是优化项

"装个 200MB 的 Electron 就为了画个框"是这个产品最容易被拒绝的理由。

→ 单 exe、免安装、常驻内存 10MB 级。

## 4. 非目标（v1 明确不做）

| 不做 | 原因 |
| --- | --- |
| 模拟点击 / 键鼠注入 | 安全边界。一旦能做，就意味着可以被用来做坏事；引导的价值不需要它 |
| 录屏 / 标注画板 / 白板 | 是另一个产品 |
| 跨机器 / 远程共享 | 需要服务端，和"单文件小工具"冲突 |
| 在 UAC 安全桌面上画 | 系统禁止，而且那正是最不该被"引导"的地方 |
| 常驻托盘的重型 GUI | 可以有托盘图标，但不做设置窗口（v1 用配置文件） |

## 5. 验收标准

| 指标 | 目标 |
| --- | --- |
| 首帧延迟（守护进程已就绪） | < 30 ms |
| 首帧延迟（冷启动，需拉起守护进程） | < 300 ms，且期间不闪任何东西 |
| 常驻内存（无遮罩） | < 12 MB |
| 常驻内存（4K 双屏显示中） | < 40 MB，且不随分辨率线性膨胀 |
| 二进制体积 | < 5 MB（单文件，无运行时依赖） |
| 坐标准确率 | 100% / 125% / 150% / 200% 缩放下均对准 |
| 模型一次调用成功率 | > 95%（错误可自解释，不需要试错） |
| 退出残留 | 0（进程退出后屏幕上不留任何窗口、任务栏不留图标） |

## 6. 已知风险

1. **钓鱼利用**：任何进程都能调起"点这里"的提示框，用来骗用户点危险按钮。
   → 必须有一个稳定、难以伪造的视觉身份（角标/水印），见 05 章。
2. **全屏独占应用**：游戏、部分播放器会盖住一切顶层窗口，遮罩不可见。
   → 明确写进文档，检测到全屏时给出降级提示，不做 hack。
3. **遮罩抢焦点导致用户输入中断**：必须靠 `WS_EX_NOACTIVATE` 严格规避。
4. **用户觉得"被打断"**：默认消失时间、动效克制程度、可一键关掉，都需要实测调。
