# 08 · 开发大纲

> 状态：草案 v0.1
>
> 这是从设计到代码的落点：仓库怎么切、类型怎么定、按什么顺序写、怎么验。

## 1. 仓库结构

```
spotlight/
├── Cargo.toml                 # workspace
├── rust-toolchain.toml        # 锁定 1.9x + msvc
├── crates/
│   ├── core/                  # 纯逻辑，零 OS 调用，可单测
│   ├── render/                # DrawOp → Pixmap（tiny-skia + cosmic-text）
│   ├── platform/              # 平台实现：win / mac
│   └── cli/                   # 二进制 spotlight.exe
└── docs/
    └── manual-test.md         # 真机验收清单
```

依赖方向**单向**，不允许反向：

```
cli ──► platform ──► core
 │         │
 └──► render ──► core
```

`core` 不允许出现 `cfg(windows)`、`unsafe`、文件系统、时间以外的任何平台假设。

## 2. core 的模块树

```
core/src
├── lib.rs
├── geom.rs        # Rect / RectF / Point，ImageRect / ScreenRect 两个 newtype
├── monitor.rs     # Monitor 描述
├── mapping.rs     # image px ⇄ screen px
├── mask.rs        # 屏幕减洞 → 矩形集合
├── layout.rs      # 卡片八方位打分
├── scene.rs       # Scene / Target / Callout / Timeout
├── effect/        # Effect trait + 内置效果
│   ├── mod.rs     # 注册表
│   ├── ring.rs  glow.rs  arrow.rs  brush.rs  pulse.rs  crosshair.rs  badge.rs
├── draw.rs        # DrawOp 指令
├── pixmap.rs      # 纯 RGBA 缓冲（平台层只认这个）
├── protocol.rs    # NDJSON 请求/响应
├── config.rs      # TOML
├── timing.rs      # auto 时长估算
└── error.rs       # 错误枚举 + hint
```

## 3. 关键类型

坐标用 **newtype** 隔离，让编译器帮你抓"图像像素当屏幕像素用"的错误——这类 bug
在运行时只表现为"框偏了"，极难查。

```rust
// geom.rs
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Rect { pub x: i32, pub y: i32, pub w: i32, pub h: i32 }

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct ImageRect(Rect);      // 截图像素
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct ScreenRect(Rect);     // 屏幕物理像素（左上原点，y 向下）
```

```rust
// mapping.rs
pub struct Segment {
    pub monitor: MonitorId,
    pub image:  Rect,        // 这张图里的哪一块
    pub screen: Rect,        // 对应屏幕上哪一块
}

pub struct CaptureMap {
    pub id: CaptureId,
    pub image_size: (u32, u32),
    pub monitors: Vec<Monitor>,
    pub segments: Vec<Segment>,
}

impl CaptureMap {
    pub fn to_screen(&self, r: ImageRect) -> Result<ScreenRect, MapError>;
}
```

```rust
// scene.rs
pub struct Scene {
    pub key: Option<String>,          // --id，用于原地替换
    pub targets: Vec<Target>,
    pub callout: Option<Callout>,
    pub effects: Vec<EffectSpec>,
    pub timeout: Timeout,
}

pub struct Target { pub rect: ScreenRect, pub step: Option<String> }

pub enum Timeout { Sticky, Seconds(f32), Auto }
```

```rust
// effect/mod.rs
pub struct Ctx<'a> {
    pub target: RectF,
    pub callout: Option<RectF>,
    pub scale: f32,               // 该显示器的 DPI 缩放
    pub theme: &'a Theme,
}

pub trait Effect {
    fn bbox(&self, cx: &Ctx) -> RectF;
    fn duration(&self) -> Duration;          // 0 = 静态
    fn draw(&self, cx: &Ctx, t: f32, out: &mut Vec<DrawOp>);
}
```

## 4. 平台抽象

只暴露 8 个方法，且全部是"你要什么"，不透露怎么实现：

```rust
pub trait Host {
    fn monitors(&self) -> Vec<Monitor>;
    fn capture(&self, req: &CaptureRequest) -> Result<Capture, HostError>;

    /// 一次性建好所有窗口：遮罩矩形 + 一个效果窗口
    fn present(&self, plan: &PresentPlan) -> Result<SceneToken, HostError>;
    /// 提交效果层位图（dirty 用于只更新进度条那一条）
    fn blit(&self, token: &SceneToken, bmp: &Pixmap, dirty: Option<Rect>) -> Result<(), HostError>;
    fn dismiss(&self, token: SceneToken, animate: bool);

    fn cursor_pos(&self) -> Point;
    fn hotkey(&self, combo: Hotkey) -> Result<HotkeyToken, HostError>;
    fn set_capture_excluded(&self, token: &SceneToken, excluded: bool);
}

pub struct PresentPlan {
    pub monitor: MonitorId,
    pub mask_rects: Vec<Rect>,       // 纯色分层窗口
    pub effect_rect: Rect,           // 逐像素 alpha 窗口
    pub hit_rect: Option<Rect>,      // 关闭按钮，相对 effect_rect
    pub dim_alpha: u8,
}
```

`platform` 里 `win` 和 `mac` 各实现一遍；没有 Mac 时 `mac` 模块先放
`todo!()` + `#[cfg(target_os = "macos")]`，保证 Windows 编译不受影响。

## 5. 线程与消息流

```
┌── 主线程（消息循环）──────────────────────────────┐
│  拥有全部 HWND、定时器、场景状态                    │
│  WM_APP_CMD  → 处理来自 IPC 的命令                 │
│  WM_TIMER    → 动画帧 / 倒计时 / 悬停轮询           │
└───────────────▲──────────────────────────────────┘
                │ PostMessage + mpsc 回执
┌───────────────┴──────────┐
│ IPC 线程（每连接一个）      │  阻塞读 NDJSON，转成 Command 丢给主线程
└──────────────────────────┘
```

三条硬规则：

1. **所有窗口操作只在主线程**。Win32 窗口有线程亲和性，跨线程操作会随机崩。
2. **不用 async runtime**。连接数是个位数，阻塞线程足够，省掉 tokio 的 1 MB+ 和复杂度。
3. **定时器只有一个**，按"下一次需要重绘的时间"动态调整间隔——静态画面时干脆不设。

## 7. 实现顺序（垂直切片）

每个切片都要求"能跑、能看、能验"，不允许"先写完三个模块再联调"。

| # | 切片 | 交付 | 验收 |
| --- | --- | --- | --- |
| S0 | Spike A/B | 两个丢弃型 demo | 点击穿透 + 截图排除都成立 |
| S1 | core 纯逻辑 | `geom` `mask` `layout` `mapping` + 单测 | `cargo test` 全绿，无 GUI |
| S2 | 第一个画面 | daemon + `present` + `show/clear/status` | 命令行出一个静态框 |
| S3 | 坐标闭环 | `capture` + mapping + DPI | 125% 缩放下误差 ≤ 1px |
| S4 | 效果 | `Effect` 注册表 + ring/badge/arrow | 切换效果不需要改渲染代码 |
| S5 | 文案卡片 | 排版 + 八方位避让 | 四个角落的目标都不遮挡 |
| S6 | 时间 | 倒计时 + 进度条 + 悬停 + 关闭 + 热键 | 悬停停表、移开继续 |
| S7 | 完整性 | 多目标 + `--file` + config + `doctor` | 配置改完立即生效 |
| S8 | 发布 | 体积/启动 bench + `install` | < 5 MB，冷启动 < 150 ms |

**S1 可以先于 S0 完成**，因为它是纯函数，不依赖任何真机验证。

## 8. 测试策略

| 层 | 方式 | 说明 |
| --- | --- | --- |
| mask 分解 | 性质测试 | 所有矩形面积之和 + 洞面积 == 屏幕面积；矩形互不重叠；并集 == 屏幕 − 洞 |
| mapping | 往返 + 边界 | 镜像、负坐标、跨屏、极端缩放（0.5×–4×） |
| layout | 快照 | 给定目标位置 → 断言卡片落在期望方位 |
| effect | 离屏渲染快照 | 把 Pixmap 存成 PNG 比对，**不需要桌面** |
| protocol | 表驱动 | 缺字段、超长、未知字段、非法 JSON |
| CLI | 集成测试 | 直接跑编译出的二进制：帮助、退出码、参数错误、坏场景文件 |
| 真机行为 | 手工清单 | 穿透、悬停、DPI 切换、锁屏、Alt+Tab、多屏 |

离屏渲染快照是这个项目最值钱的测试：效果层是纯函数，CI 里就能跑，不用起 GUI。

## 9. 风险表

| 风险 | 概率 | 影响 | 验证时间 | 预案 |
| --- | --- | --- | --- | --- |
| `HTTRANSPARENT` 后下层 hover 不刷新 | 中 | 中 | S0 | 关闭按钮改为独立小窗口 |
| `WDA_EXCLUDEFROMCAPTURE` 对 `BitBlt` 无效 | 中 | 高 | S0 | 截图前主动隐藏 + 等两帧 |
| 窗口过多导致合成抖动 | 低 | 中 | S1 | 超过 24 块退化为整屏位图 |
| 中文字体加载慢 / 缺字 | 中 | 中 | S5 | DirectWrite 按名取字体文件 |
| 混合 DPI（笔记本 + 外接屏） | 中 | 高 | S3 | 逐屏窗口，天然规避；需真机 |
| 体积超 5 MB | 中 | 中 | S4 | 切 DirectWrite 排版，砍 cosmic-text |
| macOS 拿不到 TCC 权限 | 高 | 高 | M6 | 必须 .app + 签名；没有账号只能自用 |

## 10. 工程约定

| 项 | 约定 |
| --- | --- |
| 错误 | `core` 用枚举 + `hint()`；CLI 边界统一转成 `{code, message, hint}` |
| `unsafe` | 只允许出现在 `platform`，每块加 `// SAFETY:` 说明 |
| 日志 | 默认关闭；`--verbose` 写 `%LOCALAPPDATA%\spotlight\logs\`，滚动 3 个文件 |
| 格式化 | `cargo fmt` + `cargo clippy -- -D warnings` |
| 提交 | Conventional Commits：`feat(win): 点击穿透` |
| 版本 | 0.1.0 起，`--version` 打 semver + git hash |
| MSRV | 锁在 `rust-toolchain.toml`，不追新 |

## 11. 第一个 commit 写什么

```bash
cargo new --lib crates/core
cargo new --lib crates/render
cargo new --lib crates/platform
cargo new --bin crates/cli
```

然后立刻写 `core::geom` 和 `core::mask` 的测试——在没有窗口的情况下，先把"屏幕减洞"
这个算法钉死。它是整个渲染的地基，也是最容易写错的地方。
