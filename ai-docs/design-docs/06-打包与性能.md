# 06 · 打包与性能

> 状态：草案 v0.1
>
> 这一章守住 00 章里的约束 C5：**体积和占用是产品前提，不是优化项。**

## 1. 目标

| 指标 | 目标 | 底线 |
| --- | --- | --- |
| 单文件体积 | **< 5 MB** | 6 MB |
| 冷启动到首帧 | **< 150 ms** | 300 ms |
| 热调用（守护进程在跑） | **< 30 ms** | 50 ms |
| 常驻内存（空闲） | **< 12 MB** | 15 MB |
| 运行时依赖 | 0（不装 VC++ 运行库、不装 WebView2、不需要 .NET） | — |

## 2. 体积预算

| 组件 | 估算 | 备注 |
| --- | --- | --- |
| `windows` crate（手挑 feature） | 400–700 KB | 只开用到的模块，千万别全开 |
| `tiny-skia` | ~250 KB | 光栅化 |
| ~~`cosmic-text` + `swash` + `fontdb`~~ | **0** | **已改用 GDI `DrawTextW` 出 alpha 掩膜**，省掉约 1 MB 和字体目录扫描 |
| `serde` + `serde_json` | ~250 KB | |
| `toml` | ~150 KB | 可以换成手写解析省 100KB，不值得 |
| 自身代码 | ~300 KB | |
| **合计（估）** | **1.5–2.2 MB** | 5 MB 预算余量很大 |

### 压缩手段

```toml
[profile.release]
opt-level     = "z"        # 也试试 "s"，实测取小
lto           = "fat"
codegen-units = 1
panic         = "abort"
strip         = "symbols"
```

- **不引入**：`regex`（用简单字符串匹配）、`chrono`（用 `std::time`）、`tokio`
  （不需要 async）、`anyhow`（自己写 30 行错误类型）
- **用系统 API 换掉库**：PNG 编码走 WIC（Windows）/ ImageIO（macOS），
  省掉 `png` + `flate2` 约 400 KB
- 不开 `build-std`：要 nightly，收益远小于维护成本

### 体积的"储备方案"

文字已经走系统排版引擎（GDI / CoreText），所以最大的那块体积风险提前消掉了。
如果仍然超预算，依次砍：

1. `tiny-skia` → 用 GDI+ / Direct2D 画圆角与描边（省 ~250 KB，多写 unsafe）
2. `serde_json` → 手写最小 JSON 解析（省 ~200 KB，不值当）
3. 砍功能特性（主题、多目标），最后才考虑这个

## 3. 启动耗时

```
CLI 进程启动        3–8 ms
  └ 连接管道        < 1 ms
  └ [未运行] CreateProcess 拉起 daemon   20–40 ms
  └ daemon 初始化（注册窗口类、枚举显示器）  3–8 ms
  └ 首次 show（排版 + 光栅化 + 提交）      8–20 ms
────────────────────────────────────────────
冷启动合计  ≈ 40–80 ms          （预算 150 ms）
热调用合计  ≈ 4–10 ms           （预算 30 ms）
```

### 三个必须避免的隐藏开销

1. **字体库扫描**。`fontdb` 扫 `C:\Windows\Fonts` 可能要 50–200 ms，是冷启动的头号杀手。
   - 做法：不扫全盘。已知 family 名时，用 DirectWrite 的 `IDWriteFontFile` 直接定位文件，
     再交给 swash。中文用 `Microsoft YaHei UI`，mac 用 `PingFang SC`。
   - 首次确实需要扫描时，**在后台线程做**，不要阻塞首帧。
2. **配置文件读取**。不要启动就读 config，等第一次需要样式时再读。
3. **预创建窗口**。不要。按需创建，并复用。

### 度量

`show --json` 直接带计时，便于事后定位回归：

```json
{"ok":true,"scene":"s-3",
 "timings":{"cli_ms":3.1,"spawn_ms":0,"ipc_ms":0.4,"layout_ms":0.2,
            "raster_ms":6.8,"present_ms":1.9,"total_ms":12.4}}
```

## 4. 内存

| 场景 | 增量 | 来源 |
| --- | --- | --- |
| 守护进程空闲 | 0（基线 ~10 MB） | 二进制映射 + 堆 + 消息队列 |
| 静态显示 1080p | +1.5–2 MB | 效果窗口位图 + 字形缓存 |
| 动画中 | +0 | 复用同一块位图 |
| 4K 双屏 | +2 MB | **不随分辨率膨胀**（遮罩窗口无位图） |

效果窗口的尺寸是 `target ∪ callout ∪ 各效果包围盒`，通常 400×300 以内（约 0.5 MB）。
只有效果画得很大时才会涨——设置上限：超过屏幕面积 40% 时降到 1/2 分辨率再拉伸。

## 5. 分发（Windows）

### 产物

```
spotlight.exe                 # 单文件，静态 CRT
```

### 三种用法

| 模式 | 配置位置 | 场景 |
| --- | --- | --- |
| 绿色 | 同目录 `spotlight.toml`（存在即生效） | U 盘、临时试用 |
| 默认 | `%APPDATA%\spotlight\config.toml` | 日常 |
| 安装 | 同默认 | 加进 PATH 后到处能调 |

数据目录（截图缓存等）默认在 `%LOCALAPPDATA%\spotlight`，可以用环境变量
`SPOTLIGHT_HOME` 整体挪走——便携部署和自动化测试都靠它。

### `spotlight install`（无需管理员）

1. 复制自身到 `%LOCALAPPDATA%\Programs\Spotlight\spotlight.exe`
2. 把该目录加进**用户级** PATH（`HKCU\Environment`），广播 `WM_SETTINGCHANGE`
3. 可选 `--autostart`：在启动文件夹放一个快捷方式（**不用** `Run` 注册表键，卸载更干净）
4. 卸载：`spotlight uninstall` 反向执行，并删除配置（需 `--purge` 确认）

### 签名

v1 不签名。代价是首次运行会碰到 SmartScreen "未知发布者"警告。

缓解办法：

- 发布页给出 SHA256，说明"未签名，可校验哈希"
- 文档写清楚为什么（个人项目、无证书）
- 真要做大了，再买 OV 证书（约 ¥2000/年）

## 6. 分发（macOS，后补）

- **必须是 `.app` bundle**。裸二进制拿不稳 TCC 屏幕录制权限——权限绑定 bundle id
  与代码签名，每次重编译都可能要重新授权。
- 通用二进制：`arm64` + `x86_64`（`lipo` 合并）
- 发布需 `codesign` + `notarytool` 公证，否则 Gatekeeper 直接拦
- 没有开发者账号时：只能本地 ad-hoc 签名自用，**不能分发给别人**
- 这也是为什么 D4 把 macOS 排到后面：不是代码难，是**机器和账号**是硬门槛

## 7. 质量门槛（CI 卡点）

| 门槛 | 规则 |
| --- | --- |
| 体积 | `spotlight.exe` > 6 MB → 失败 |
| 启动 | 手工测（`doctor` 里能看到守护进程 ping）；独立的 `bench` 命令已决定不做 |
| 内存 | 静态场景峰值 > 20 MB → 失败 |
| 单测 | core 全部通过 |
| 快照 | 离屏渲染的 PNG 与基准图差异为 0 |

单测和渲染快照能自动化；体积需要本地构建后量，启动/内存手动测。
